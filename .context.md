# TabBellus Project Context Manifest
**Project Version:** 1.2.2

## 1. Database Schema (Dexie.js)
**Database Name:** `TabBellusDB` (Version 3)

### Tables & Indexes
- **`spaces`**: `++id, name, createdAt, deletedAt`
  - `name` (string): User-provided space label.
  - `createdAt` (timestamp): Creation date.
  - `deletedAt` (timestamp, optional): Soft-delete marker.
  - `isPinned` (boolean, optional): User favorite status for 4-tier sorting.
  - `color` (string, optional): Chrome tab group color tag token.
- **`tabs`**: `++id, spaceId, url, order, [spaceId+order]`
  - `spaceId` (number): FK to `spaces`.
  - `url` (string): Full browser URL.
  - `title` (string, optional): Tab title captured at the time.
  - `favicon` (string, optional): Captured icon URL.
  - `order` (number): Relative position in the space.
- **`readLater`**: `++id, url, addedAt, status`
  - `status`: `'unread' | 'read' | 'archived'`

## 2. Core Services & Architecture
Located in `src/lib/`, `src/core/`, and `src/pro/`.

### **Core Extension Point & Gating Infrastructure** (`src/core/`)
- **`contracts/index.ts`**: Pure TypeScript interfaces (`EntitlementStatus`, `LicensingContract`, `ProModuleMetadata`, `ProModule`, `FeatureSlotRegistration`, `SyncState`, `SyncTelemetry`, `SyncStatus`, `SyncResult`, `SyncProvider`, `ConditionField`, `ConditionOperator`, `RuleCondition`, `ActionType`, `RuleAction`, `TabRule`, `RuleEvaluationResult`, `RulesContract`) owned by Free Core.
- **`contracts/sync.ts`**: Pure TypeScript contracts defining sync lifecycle states (`'idle' | 'syncing' | 'synced' | 'error' | 'offline' | 'locked'`), telemetry models (`SyncTelemetry`), and `SyncProvider` capability interfaces with optional E2EE methods (`setupEncryption?`, `unlockVault?`, `lockVault?`).
- **`contracts/rules.ts`**: Pure TypeScript contracts for the tab automation rules engine. `ConditionField` (`'url' | 'domain' | 'title'`), `ConditionOperator` (`'equals' | 'contains' | 'startsWith' | 'endsWith' | 'wildcard' | 'regex'`), `RuleCondition`, `ActionType` (`'group' | 'space' | 'pin' | 'mute' | 'discard'`), `RuleAction`, `TabRule` (id, name, enabled, priority, matchAll, conditions, actions, timestamps), `RuleEvaluationResult`, and the `RulesContract` capability interface (`getRules`, `saveRules`, `evaluateTab`, `executeActions`, `subscribe`).
- **`contracts/registry.ts`** (`ContractRegistry`, `NullLicensingEngine`, `NullSyncProvider`, `NullRulesEngine`): Singleton registry managing decoupled licensing provider registration, sync provider registration, rules provider registration, Pro module discovery, feature slot collections, and subscriber notifications. Rules provider surface mirrors the sync provider pattern: `registerRulesProvider(provider)`, `getRulesProvider()`, `getRulesSnapshot()` (synchronous current rule array), and `subscribeRules(callback)`, all restored to `NullRulesEngine` defaults on `reset()`. **`getRulesSnapshot()` returns the internal `currentRules` array reference directly (not a copy)** — `currentRules` is only ever reassigned wholesale in `updateRulesAndNotify`, never mutated in place, so the reference stays stable between actual rule-list changes. This is required for `useRules()`'s `useSyncExternalStore` contract: a fresh array on every call fails `Object.is` on every render and causes an infinite re-render loop (regression fixed post-Phase 42 — see Knowledge Base).
- **`hooks/useEntitlement.ts`** (`useEntitlement`): `useSyncExternalStore`-powered reactive hook querying active entitlement status with fail-open fallback (`isPro: false`, `tier: 'free'`).
- **`hooks/useSyncStatus.ts`** (`useSyncStatus`): `useSyncExternalStore`-powered reactive hook subscribing to `contractRegistry.subscribeSync()` and querying active sync provider status with fail-open fallback (`state: 'idle'`, `isConnected: false`, `telemetry: { pendingMutations: 0, encrypted: false }`).
- **`hooks/useRules.ts`** (`useRules`): `useSyncExternalStore`-powered reactive hook subscribing to `contractRegistry.subscribeRules()` and reading `contractRegistry.getRulesSnapshot()` with fail-open fallback (`rules: []`, `loading: false`). Exposes imperative `saveRules(rules)` (delegates to `contractRegistry.getRulesProvider().saveRules()`, swallowing errors) and `applyRulesToWindow(windowId?)` (sends `{ type: 'APPLY_RULES_TO_WINDOW', windowId }` via `chrome.runtime.sendMessage` to the background `rulesDispatcher`, failing open to `{ processed: 0, matched: 0 }` on any error or malformed response).
- **`components/FeatureGate.tsx`** (`FeatureGate`): Declarative UI gating wrapper rendering `children`, `fallback`, or `loadingFallback` based on required entitlement tier (`pro` | `enterprise`).
- **`index.ts`**: Free Core barrel export.
- **Zero-Contamination Boundary**: Free core interacts strictly through these interfaces and MUST NEVER import from `src/pro/`.

- **`licensing/index.ts`** (`ProLicensingEngine`): Driver implementing `LicensingContract` for entitlement verification, cache management, fail-open offline-first grace states, and compile-time-guarded dev testing harness (`DEV-`/`TB-TEST-` key prefix bypass, `VITE_DEV_ENTITLEMENT` env var fallback, `window.__tabbellusDev` console helpers — all tree-shaken from production bundles).
- **`sync/api/types.ts`**: Typed interfaces for Google Drive API layer: `DriveFileMetadata`, `DriveFileListResponse`, `DriveApiResult<T>` (discriminated union), and `VaultPayload` (JSON sync envelope with schema version, client timestamp, payload/ciphertext, optional E2EE initialization vectors, and explicit `isEncrypted` flag).
- **`sync/api/googleAuthClient.ts`** (`GoogleAuthClient`, `googleAuthClient`): Singleton wrapping `chrome.identity.getAuthToken` for OAuth2 token lifecycle management. Methods: `getAuthToken(interactive?)`, `invalidateToken(token)`, `revokeToken(token)`. Normalizes `chrome.runtime.lastError` and runtime exceptions into typed `DriveApiResult`.
- **`sync/api/googleDriveClient.ts`** (`GoogleDriveClient`, `googleDriveClient`): Singleton Google Drive v3 REST client for `appDataFolder` vault file CRUD. Methods: `findVaultFile(fileName?)`, `downloadVaultFile(fileId)`, `uploadVaultFile(content, existingFileId?, fileName?)`. Uses `multipart/related` uploads and implements 401 auto-recovery protocol (invalidate → fresh token → single retry). Normalizes 403, 404, 5xx, and network offline errors without throwing.
- **`sync/api/index.ts`**: Barrel re-export of all sync API types, classes, and singletons. Zero imports from `src/core/` implementation files.
- **`sync/engine/types.ts`**: Types for snapshot serializer, LWW diff engine, and persistent storage: `SyncVaultSnapshot`, `ReconciliationResult`, `SyncStorageState` (with `isEncrypted` and `vaultSalt`).
- **`sync/engine/snapshotSerializer.ts`** (`SnapshotSerializer`): Stateless serializer extracting full Dexie snapshots (`spaces`, `tabs`, `readLater`) in read transactions, writing updates in atomic read-write transactions (`bulkPut`), and validating schema integrity.
- **`sync/engine/diffEngine.ts`** (`DiffEngine`): Record-level LWW multi-master reconciliation engine. Preserves soft-deletion tombstones (`deletedAt`) to prevent deletion resurrection, remaps space auto-increment IDs and tab `spaceId` foreign keys, and converges Read Later items to `'archived'` state.
- **`sync/engine/syncEngine.ts`** (`SyncEngine`, `syncEngine`): Stateful sync provider implementing `SyncProvider` from `@/core/contracts/sync.ts`. Orchestrates full 8-step synchronization cycle (silent auth check -> Drive find -> download & decrypt snapshot -> local Dexie snapshot -> DiffEngine -> local Dexie write -> encrypt & Drive upload -> status/telemetry dispatch). Manages E2EE lifecycle with `setupEncryption(passphrase)`, `unlockVault(passphrase)`, and `lockVault()`. Gracefully enters `'locked'` state when remote is encrypted without active session keys. Registered into `contractRegistry.registerSyncProvider(syncEngine)`.
- **`sync/components/SyncSettingsCard.tsx`** (`SyncSettingsCard`): High-density UI card rendered inside the Settings Data tab via declarative feature slot `data-tab-sync`. Displays connection status pills (`synced`, `syncing`, `offline`, `error`, `disconnected`, `locked`), E2EE security badges (`E2E Encrypted` vs `Standard Sync`), relative last-synced telemetry, "Sync Now" action, "Disconnect" option, "Enable E2EE" / "Lock" controls, and "Unlock Vault" CTA opening `VaultUnlockModal`.
- **`sync/components/EncryptionSetupModal.tsx`** (`EncryptionSetupModal`): Controlled Radix dialog with zero-knowledge disclaimer, show/hide passphrase toggles, live 4-segment strength bar, confirmation match checks, and initial encrypted vault upload.
- **`sync/components/VaultUnlockModal.tsx`** (`VaultUnlockModal`): Controlled Radix dialog prompting for passphrase on locked devices, inline error feedback, and double-confirmation emergency cloud reset flow.
- **`sync/components/{encryptionModalLogic,unlockModalLogic}.ts`**: Side-effect-free pure helpers for passphrase strength calculation (score 0-4, labels), validation, and draft verification.
- **`sync/crypto/types.ts`**: Typed interfaces and error classes for client-side zero-knowledge end-to-end encryption (E2EE): `EncryptedVaultEnvelope`, `KeyDerivationOptions`, `KeyStoreRecord`, `CryptoErrorCode`, `CryptoEngineError`.
- **`sync/crypto/webCrypto.ts`** (`WebCryptoEngine`): Pure W3C SubtleCrypto engine implementing PBKDF2-HMAC-SHA256 (600,000 iterations) key derivation, AES-256-GCM authenticated encryption/decryption with 12-byte random IVs, chunked Base64 helpers (zero Node.js `Buffer` dependency), and `OperationError` auth tag verification mapping directly to `INVALID_PASSPHRASE`.
- **`sync/crypto/keyStore.ts`** (`SessionKeyStore`, `sessionKeyStore`): Ephemeral session key store managing active vault unlock state in `chrome.storage.session` (`tabbellus_vault_session`) with fast in-memory caching and graceful fail-open degradation to in-memory only storage.
- **`sync/crypto/index.ts`**: Barrel re-export of all crypto types, `WebCryptoEngine`, `SessionKeyStore`, and `sessionKeyStore`.
- **`sync/index.ts`**: Root barrel export for Pro sync subsystem (API, Engine, Crypto, and Components layers).
- **`[modules]/`**: Decoupled Pro capability drivers registering dynamically via runtime hooks without circular dependencies.
- **`rules/engine/matcher.ts`** (`RuleMatcher`): ReDoS-safe condition evaluator. `evaluateCondition(tab, condition)` extracts the target field (`url`, `title`, or `domain` via `tryParseHost` from `@/lib/sessionUtils`), normalizes case per `caseSensitive`, and evaluates `equals`/`contains`/`startsWith`/`endsWith` directly. `wildcard` patterns are escaped and compiled into fully-anchored RegExp objects (`*` → `.*`, `?` → `.`) so no raw user pattern reaches the engine ungoverned; `regex` patterns are capped at 250 characters and compiled inside a try/catch as a risk-reduction heuristic (not a runtime execution timeout). `evaluateRule(tab, rule)` combines conditions per `rule.matchAll` (AND) or OR, returning `false` for a rule with zero conditions.
- **`rules/engine/executor.ts`** (`RuleExecutor`): Applies matched `RuleAction[]` to a live Chrome tab. Each action (`pin`, `mute`, `discard`, `group`, `space`) is wrapped independently so one failure never blocks the rest. `group` queries `chrome.tabGroups.query({ windowId })`, joins an existing group by case-insensitive title match, or creates one via `chrome.tabs.group` + `chrome.tabGroups.update`. `space` resolves live tab details via `chrome.tabs.get` and calls `spaceService.addTabToSpace`, silently ignoring `DUPLICATE_TAB`.
- **`rules/engine/rulesEngine.ts`** (`RulesEngine`, `rulesEngine`): Concrete `RulesContract` implementation. Hydrates from `ruleStorage` on construction (`getRules`/`evaluateTab` await hydration for deterministic reads), sorts rules ascending by `priority`, and evaluates enabled rules in order — first match wins (`evaluateTab`). `saveRules` re-sorts, persists via `ruleStorage.saveRules`, and notifies subscribers. `executeActions` delegates to `RuleExecutor`. **Also binds a `chrome.storage.onChanged` listener** (`bindStorageListener`, watching `RULES_STORAGE_KEY` in `sync`/`local`) that re-runs hydration whenever the rules key changes — required because the sidepanel and the background service worker each hold their own separate `RulesEngine` singleton (one per JS execution context; see §2 Background Worker and Knowledge Base Phase 42.6), so without this listener an edit made via the sidepanel UI would never reach the background's copy (the one that actually drives live automation) until the service worker happened to restart.
- **`rules/storage/ruleStorage.ts`**: Persists the rule array to `chrome.storage.sync` (key `tabbellus_tab_rules`) with automatic `chrome.storage.local` fallback on quota/permission errors. Exposes `loadRules()`, `saveRules(rules)`, `clearRules()`.
- **`rules/storage/templates.ts`** (`RULE_TEMPLATES`): Four starter presets (Development → group "Dev"/purple on github.com or gitlab.com; Google Workspace → group "Work"/blue on docs/sheets.google.com; Media & Streaming → auto-mute on youtube.com or twitch.tv; Documentation → group "Docs"/green on developer.mozilla.org or stackoverflow.com), each an `Omit<TabRule, 'id' | 'createdAt' | 'updatedAt' | 'priority'>` ready for instantiation.
- **`rules/components/RuleManagerCard.tsx`**: High-density settings card (Behavior tab feature slot `behavior-tab-rules`). Header row: "Apply Rules Now" (resolves its own window via `useWindowId()` — required, since the background service worker has no window of its own and cannot reliably infer "current window" — and invokes `useRules().applyRulesToWindow(windowId)`, spinning icon, toast `"Applied rules: X tabs organized"`), "Templates" (opens `<TemplatePickerModal>`), "New Rule" (opens `<RuleEditorModal>` in create mode). Empty state offers "Create Custom Rule" / "Browse Starter Presets" CTAs.
- **`rules/components/RuleEditorModal.tsx`**: Controlled Radix Dialog for create/edit. Rule name input, Match ALL (AND) / Match ANY (OR) segmented control, dynamic condition rows (`ConditionRow.tsx`: field/operator selects, value input with live regex validation border+helper text, case-sensitivity checkbox, remove), dynamic action rows (`ActionRow.tsx`: action-type select; `group` reveals name input + `<ColorPickerGrid>`; `space` reveals a `useSpaces()`-backed dropdown), Save button gated by `validateRuleDraft()` (non-empty name, ≥1 condition, all values populated, no invalid regex).
- **`rules/components/TemplatePickerModal.tsx`**: Controlled Dialog listing `RULE_TEMPLATES` with one-click "Add Rule" buttons; `instantiateTemplate()` generates a UUID and appends at the lowest evaluation precedence (`priority = max(existing) + 1`) with fresh `createdAt`/`updatedAt`.
- **`rules/components/ruleListActions.ts`, `ruleEditorLogic.ts`, `templateActions.ts`**: Pure, independently-testable helpers backing the three components above (list mutations, priority reorder/re-normalization, summary badge formatting, draft validation, regex checking, template instantiation) — extracted so business logic is unit-testable without a DOM testing library (this project has neither jsdom nor `@testing-library/react`; component tests use `renderToString` for structural assertions plus direct calls into these pure functions for behavior).

### **SpaceService**
- `captureCurrentWindow(spaceName)`: Validates current window tabs, filters internal `chrome://` URLs, and performs an atomic transaction to save `Space` and related `Tabs` records.
- `addTabToSpace(spaceId, tab)`: Adds tab to space with duplicate URL checking within target space (throws `DUPLICATE_TAB` error on duplicate URL).
- `createEmptySpace(spaceName)`: Atomically inserts a new empty `Space` into Dexie without capturing current window tabs, separating modal creation from active session captures.
- `restoreSpace(spaceId)`: Fetches ordered tabs and opens them in a new focused Chrome window with staggered loading (tab storm prevention). Wraps `chrome.sidePanel.open` in try/catch and uses declarative `chrome.sidePanel.setOptions` to safely handle gesture token expirations. Emits a decoupled restore event to listeners.
- `createSpaceFromTabs(name, tabs)`: Low-level atomic creation of a Space from an explicit list of tabs. Handles fallback naming for unnamed groups.
- `duplicateSpace(spaceId)`: Atomically duplicates a Space and its tabs into "Copy of [Name]" preserving relative tab order.
- `moveTabBetweenSpaces(tabId, targetSpaceId)`: Atomically moves a tab to a target space with duplicate URL prevention, appending to highest order index and returning original position metadata.
- `copyTabToSpace(tabId, targetSpaceId)`: Atomically clones a tab to a target space with duplicate URL prevention at highest order index.
- `updateSpaceDetails(spaceId, name, color)`: Atomically updates space name and color metadata in IndexedDB.
- `updateSpaceColor(spaceId, color)`: Updates space color token metadata in IndexedDB.
- `updateSpaceName(id, newName)`: Updates space name in IndexedDB.
- `toggleSpacePin(spaceId)`: Toggles user pinned status on a space for priority sorting.
- `getTabsForSpace(spaceId)`: Fetches sorted tab records for a space from Dexie.
- `appendSpaceTabsToWindow(spaceId, windowId)`: Safely appends a space's tabs into an existing Chrome window ID with staggered loading, deduplicating against currently open window URLs and returning typed telemetry (`AppendTabsResult: { total, appended, skipped }`).
- **Database Boundary Encapsulation**: Exposes query providers (`getSpacesOrderedQuery`, `getSpacesNewestFirstQuery`, `getSpaceByIdQuery`, `getTabsForSpaceQuery`, `getSpacesWithTabsQuery`) and CRUD helpers (`softDeleteSpace`, `undoDeleteSpace`, `hardDeleteSpace`, `getSpaceById`, `getTabById`, `deleteTab`, `restoreTab`, `restoreTabPosition`) to prevent raw database queries or engine handles from leaking into the UI.

### **BookmarkService** (`src/lib/bookmarkService.ts`)
- `getBookmarkTree()`: Safely wraps `chrome.bookmarks.getTree()` with try/catch fallback to return the browser bookmark hierarchy.

### **TabService** (`src/lib/tabService.ts`)
- `focusOrCreate(url)`: Normalizes URLs and checks all open tabs across all windows. If a matching URL is found, focuses the target tab and its parent window via `chrome.windows.update` and returns typed telemetry `{ action: 'focused', tabId, windowId }`; otherwise creates a new tab and returns `{ action: 'created', tabId, windowId }`.
- `calculateDuplicates(tabs)`: Identifies duplicate tabs by normalized URL, prioritizing Pinned > Active > Lowest Index.
- `getTabZoom(tabId)` / `setTabZoom(tabId, zoomFactor)`: Queries and adjusts tab zoom factor clamped between 0.25 and 5.0.

### **MediaService** (`src/lib/mediaService.ts`)
- `toggleMediaPlayback(tabId)`: Injects a script via `chrome.scripting.executeScript` (with `allFrames: true`) into the target tab to toggle `<video>` and `<audio>` element playback. Returns typed `MediaToggleResult: { success: boolean; state?: 'playing' | 'paused'; error?: string }`. Gracefully handles restricted origins (`chrome://`, Chrome Web Store) and sandboxed iframes via try/catch error normalization.

## 3. MANDATORY CUSTOM ABSTRACTIONS
To prevent context amnesia, code duplication, and inconsistent UI patterns, developers and AI agents MUST strictly use these established project abstractions instead of native browser fallbacks or raw primitives:

### **1. User Feedback & Notifications (`useToast`)**
- **STRICT RULE:** NEVER use native `alert()`, `confirm()`, or raw unstyled inline error text for user notifications. ALWAYS use `const { toast } = useToast()` from `@/components/ui/Toaster`.

### **2. Clipboard Management (`useClipboard`)**
- **STRICT RULE:** NEVER invoke `navigator.clipboard.writeText()` directly inside components. ALWAYS use `const { copy } = useClipboard()` from `@/hooks/useClipboard` to ensure automated temporary success states and consistent error handling.

### **3. Tab & List Row Items (`InteractiveRow`)**
- **STRICT RULE:** NEVER build custom list item rows or flex containers from raw `<div>` elements for tab or space listings. ALWAYS use the `<InteractiveRow>` compound component primitive (`<InteractiveRow.Leading>`, `<InteractiveRow.Title>`, `<InteractiveRow.Actions>`, `<InteractiveRow.Action>`) from `@/features/tabs/components/InteractiveRow`.

### **4. Favicons & Icon Fallbacks (`SmartFallbackIcon`)**
- **STRICT RULE:** NEVER render unhandled raw `<img>` icons for website favicons. ALWAYS pair favicon images with `<SmartFallbackIcon url={url} favicon={favicon}>` from `@/components/ui/SmartFallbackIcon` to guarantee a 3-tier resolution cascade (Tier 1: Native URL -> Tier 2: Chromium `_favicon` cache -> Tier 3: Context Lucide icon / Globe fallback) with zero layout shift.

### **5. Tooltips & Text Truncation (`TooltipSimple` & `TooltipOverflow`)**
- **STRICT RULE:** NEVER use native HTML `title="..."` attributes on main text elements or raw Radix tooltip boilerplates directly. ALWAYS use `<TooltipSimple content="...">` from `@/components/ui/Tooltip` for action buttons and `<TooltipOverflow text="..." isTruncated={...}>` (paired with `useIsTruncated`) for truncated titles.

### **6. Context & Dropdown Menus (`ContextMenu` & `DropdownMenu`)**
- **STRICT RULE:** NEVER build custom fixed-position context menu divs or raw browser context listeners. ALWAYS use the styled Radix UI primitives (`<ContextMenu>`, `<ContextMenuContent>`, `<ContextMenuItem>`) from `@/components/ui/context-menu` or `@/components/ui/dropdown-menu`.

### **7. Database Queries & Domain Encapsulation (`spaceService`, `tabService`, `readLaterService`)**
